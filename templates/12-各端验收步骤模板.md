# 各端验收步骤（小白照做版）

> 读者是不懂本项目、拿到文档照着点就能测的人：不看代码、不碰数据库、不看接口。
> 命名：`req-docs/需求N-XXX/<需求名>各端验收步骤.md`。

## 编写纪律（硬）

1. **每步四件套**，单行可打勾：`- [ ] **A1** 操作：<点哪里／输入什么>｜预期：<看到什么>｜判据：<怎么算过>`，三段顺序固定，用全角 `｜` 分隔。
2. **编号** `A1…An`／`B1…Bn`／`C1…Cn`（后台＝A、C 端＝B、商户端＝C），不跳号不重号；新步骤追加到所属分类末尾，不重排已有编号。
3. **文案原样引用**（按钮／弹窗标题／卡名／门店名），判据靠文案比对，不改写。
4. **零技术纪律**：命令行／启动脚本／端口／日志／SQL／表名字段名／接口路径与响应／错误码／源码文件名行号／分支名／内部 id 一律不写；门店、房间、卡、会员用业务名或手机号指认。
5. 同一功能在不同角色门户入口可能分叉，**按门户分别写全路径**；页面结构用词与页面实际一致。
6. 拦截类用例（次数用尽／已过期等）写在对应步骤内的「预期＋判据」里，不单列章节。
7. 没实机点过的段落显式标「按源码推导、未实机点过」。

```markdown
## C. 商户端
- [ ] **C1** 操作：｜预期：｜判据：

**C 段结论**：实际做到第 ____ 步；异常现象：____________

```

## 用例覆盖要求

正向主流程之外必须覆盖**反向拦截**：次数用尽、卡已过期、仅到店卡走线上、一卡两占、超每日上限、跨门店不适用、重复核销幂等。

## 写完自查

- 条目数核对、编号连续无重号。
- 零技术纪律 grep 自查零命中：`curl|http://|SQL|SELECT|端口|错误码|代码块围栏`。
- 清掉指向已删章节的悬空引用。
